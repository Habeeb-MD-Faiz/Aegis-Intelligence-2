The stake

This is an AI agent with a funded wallet and permission to buy things.

x402 lets an agent discover a service it has never used, pay for it in one round trip, and get the resource. No account, no key, no human in the provisioning path. That's the feature.

It's also the problem. The control that used to gate spending — a human issuing a credential — is gone, and nothing replaced it.

The thesis

We don't stop the injection.
We make it financially inert.

We don't touch the model, the prompt, or the retrieval path.
The agent still gets compromised. It just can't spend anything when it does.

Why it can't be walked around

Three properties do the work

01

Credential custody

Provider secrets live in the guard, read in exactly one place, and never reach a response, a log line, or the ledger.

02

Catalog-bound payees

An agent names a task or a provider we already know. It cannot supply a URL, an address, or an amount.

03

Fail closed

If the policy engine raises, the answer is no. A guard that opens when its own evaluation crashes is not a guard.

These are structural, not procedural. None of them depend on the agent behaving well.

Act 3 — it isn't a blocklist

Autonomy without uncontrolled authority

Approved

Within every rule. Paid automatically, no human touched it.

Human review

Legitimate but above the autonomous limit. Routed to a person.

Blocked

Broke a rule. Refused, with the failing check recorded.

✓Request Frequency Limit Within frequency limit (3 of 25 in the last 24h).
✓Provider Allow List 'Bloomberg' is an allowed provider.
✓Daily Budget Within daily budget ($1,240.00 of $5,000.00).
✗Amount Threshold $150.00 exceeds the autonomous limit of $100.00; human approval required.

A decision nobody can explain isn't governance. Every rule reports its own verdict and the numbers it saw.

The next thing an attacker tries

"If the agent is prompt-injected, what stops it turning your guardrails off?"

The record

A tamper-evident decision ledger

Every final decision becomes a hash-linked block: what was requested, which provider, how much, what was decided, why, by whom. Altering any past record breaks every hash after it.

LOCAL

Hash-linked and verified on read

25 blocks committed. verify_blockchain() re-derives every hash and names the first tampered block.

ON-CHAIN

Chain head anchors to Base Sepolia

Once a funded key is configured, rewriting local history also requires altering a record we don't control. The API reports whether an anchor was actually written — we never claim one we didn't.

We deliberately don't call the local file a blockchain. It's a single-writer append-only log — saying so is the stronger position, not the weaker one.

The closer

It watched itself work, and it's proposing a rule change.

POLICY BUILDER · SUGGESTION

"You've manually approved Skyscanner above the autonomous limit 3 times this week. Consider raising the limit to $150."

CONFIDENCE 78  ·  EVIDENCE 3  ·  RECOMMENDATION: RELAX

Nothing applies itself. A suggestion is a recommendation until a human applies it on the control plane — a governance system that rewrites its own rules unsupervised is exactly the failure mode we exist to prevent.

Why that matters more than it sounds

The parallel

We didn't beat SQL injection by getting better at sanitising strings.

We beat it by separating code from data at a chokepoint. Prepared statements meant user input could no longer become instruction, however cleverly it was written.

Prompt injection has no equivalent fix — in an LLM there is no boundary between instruction and data to enforce. You cannot parameterize natural language.

So the boundary moves from input validation to action authorization. Same structural move, one layer down.

We chose the guard, not the rail — the rail already exists and the guard didn't. Wiring real settlement is about a week; nothing in the design changes when we do.
